# 검토 지시서 틀

절차서 §5 의 판마다 함께 돌리는 검토 셋에 쓴다. 자리표시를 채워서 보낸다.

| 파일 | 누가 | 넘기는 것 |
|---|---|---|
| `sentence.md` | 문장 대조 — 덱을 쓰지 않은 다른 에이전트(읽기 전용) | 사양, 쪽 그림, 인용 기록, 원문 사본, 기사 사본 경로 |
| `composition.md` | 구성·화면 평가 — 다른 에이전트(읽기 전용) | 사양, 쪽 그림 전부, 러닝시트, 평가 기준, 원본 비교표, 카드의 겹침 판정 |
| `external_head.md` | 해석 점검 — 다른 모델 계열 | 이 머리말 + `python -m ozl.render bundle <사양>` 으로 만든 묶음 |

틀에 든 자리표시와 넣는 것:

| 자리표시 | 넣는 것 |
|---|---|
| `{CARD}` | 카드 ID |
| `{SPEC}` | 사양 경로 |
| `{BUILD}` | 빌드 폴더 |
| `{ROUND}` | 몇 번째 판 |
| `{PREV}` | 이전 판에서 짚은 것(없으면 줄을 지운다) |
| `{PRESS}` | 덱이 인용한 기사 문장(없으면 줄을 지운다) |
| `{CRITERIA}` | 평가 기준 파일의 경로 |
| `{PRESS_DIR}` | 기사 사본을 받아 둔 폴더(없으면 "없음") |

- `{CRITERIA}` 는 절차서 §5 첫 문단이 정한 파일이다. 사양 맨 위에 `style: syuka` 가 있으면 새 기준, 없으면 옛 기준이다. 구성·화면 평가는 그 파일의 나 절과 다 절 항목을 전부 본다. 기준에 항목이 늘면 `composition.md` 의 할 일 1번에 적힌 번호 범위도 함께 고친다.
- `{PRESS_DIR}` 는 덱을 만드는 세션이 인용한 기사를 받아 둔 폴더다. §5 에는 이 폴더를 만드는 단계가 없다. 받아 둔 것이 없으면 줄을 지우지 말고 "없음"이라고 적는다. 그러면 문장 대조가 `refs` 가 달린 문장을 "대조하지 못함"(심각도 중간)으로 올린다. 기사 사본은 원문 사본이다(백업에 넣지 않는 자리는 `agent/publish.md`).
- 지난 방송과의 겹침(평가 기준 나7)은 `composition.md` 만 본다. 카드의 `coverage` 칸을 읽는 것은 저장소 안의 다른 에이전트뿐이고, 그 근거는 출력의 D 절에만 적힌다. `external_head.md` 에는 넣지 않는다.
- `external_head.md` 의 `{PREV}` 와 `{PRESS}` 를 채울 때 지난 방송을 가리키는 것(영상 번호, 영상 제목, 올린 날, 그 방송이 한 말과 쓴 수치)을 적지 않는다. 구성·화면 평가의 D 절은 옮기지 않는다. 채운 머리말은 묶음과 함께 보내기 전에 `.venv/bin/python .claude/skills/syuka/deck/bundle_guard.py <채운 머리말 파일> --card <card_id>` 로 본다(묶음은 `--card` 없이 같은 명령으로 본다). 종료 코드가 0 이 아니면 보내지 않는다.
- 묶음과 이 지시서들은 독립 재대조(§5 4단계) 에이전트에게 주지 않는다.
- 영상 전사·영상 목록은 다른 모델 계열에 넘기지 않는다.
- 검토끼리 부딪히면 정확성이 이긴다. 다음 판 고쳐 쓰기 지시서에 "받지 않는 것"을 적는다.
- 마지막 판은 직전 판과의 차이를 보는 게이트를 돈다(`sentence.md` 를 쓰되 범위를 "바뀐 문장, 그리고 지우거나 옮긴 곳을 가리키는 남은 문장"으로 좁힌다).
