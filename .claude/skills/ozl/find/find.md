# /ozl find — 후보를 보고 고르기 (본 세션용)

무엇을 글로 만들지 아직 정하지 않았을 때의 순서다. 매시 수집이 쌓아 둔 후보 판을 표로 보이고, 사용자가 고르고 버리고 직접 넣은 것을 기록한 뒤, 고른 건을 한 건씩 만들기로 넘긴다. 받는 것은 있으면 분야나 낱말 하나다.

자리표시: `BV` 는 `.venv/bin/python .claude/skills/ozl/find/board_view.py`, `<자료 루트>` 는 `OZL_DESK_ROOT` 의 값(없으면 `private/desk`)이다. 시험은 `SKILL.md` 의 「공통」과 「시험 루트에서 돌릴 때」를 따른다: 세션의 환경에 `OZL_DESK_ROOT` 가 이미 있으면 명령 앞에 붙이지 않고, 없으면 `OZL_DESK_ROOT=<시험 루트>` 를 둔다. 시험 사본에서는 사본의 후보 판을 그대로 읽고, 실제 저장소에서 시험 루트만 바꿔 돌릴 때만 `--board tests/fixtures/skills/board.json` 을 준다.

## 하지 않는 것

- 수집을 돌리지 않는다. 수집과 계산 명령(`scripts/pulse_run.sh`, `ozl.signals run`)을 부르지 않고, 예약 작업이나 launchd 작업을 만들거나 켜지 않는다.
- 사실 확인을 하지 않는다. 표의 수치와 제목은 검증 전 신호다. 기사를 열어 보거나 원문을 찾는 일은 만들기 2단계에서 한다.
- 민감 소재를 표에서 빼지 않는다. 표시만 한다(사용자 결정).
- 사용자 대신 고르지 않는다. 사용자가 묻기 전에는 "이것을 권한다"고 순위를 다시 매기지 않는다.
- 후보 판, 대기열 파일, 이슈 기록을 고치지 않는다. 쓰는 것은 `BV note` 가 쓰는 고르기 기록뿐이다.

## 순서

### 1. 표를 찍는다

```bash
.venv/bin/python .claude/skills/ozl/find/board_view.py
```

- 받은 말이 분야 이름이면 `--category <분야>`, 그 밖의 낱말이면 `--match <낱말>` 을 붙인다. 분야 이름은 표 아래 "분야별 줄 수"에 나오는 것 그대로다(없는 분야를 주면 스크립트가 판의 분야 이름을 알려 준다).
- 기본은 15줄이다. 사용자가 더 보자고 하면 `--top 30` 처럼 늘린다.
- 순서는 화제 엔진이 매긴 큰 이야기 순서(`story_rank`)다. 한국어 후보가 먼저 나오고 영문 후보는 뒤에 '(영문)'으로 나온다.
- **첫 줄의 기준 시각을 본다.** 이어서 "경고: 후보 판이 2시간보다 오래됐다"가 나오면 매시 수집이 멈춘 것으로 보인다. 수집을 스스로 돌리지 않는다. 사용자에게 기준 시각과 함께 그렇게 알리고, 그 판을 그대로 볼지 묻는다.
- "후보 판이 없다"로 끝나면 그렇게 알리고 끝낸다. 만들 주제가 정해져 있으면 `/ozl make "<제목>"` 은 판 없이도 된다고 덧붙인다.

### 2. 이미 만든 글과 견준다

- 표의 '이미' 칸에는 대기열이나 고르기 기록이 화제 번호와 이슈 번호를 함께 적어 둔 것만 나온다("글 i…", "골라 둠", "대기열 m…").
- 표 아래 「이미 만든 글」 목록의 제목을 표의 제목과 견주어, 같은 사건으로 보이는 줄을 찾는다. 상태와 빠진 검토는 `.venv/bin/python -m ozl.issues status` 로 본다.
- 같은 사건의 글이 있으면 표를 보일 때 그 줄에 "이미 만든 글 i…(상태)"라고 적는다. 같은 사건인지 확실하지 않으면 "비슷한 글 i… 있음"이라고만 적는다. 같은 사건은 같은 주체가 같은 때에 한 같은 일(발표, 조치, 사고)이다. 주체만 같고 일이 다르면 다른 사건이고 '이미' 칸에 적지 않는다. 제목만으로 가리기 어려우면 그 이슈의 `issue.yaml` 에서 키워드와 다루는 까닭을 읽는다(읽기만 한다). 줄을 빼지 않는다. 뒤이은 소식이면 새 글이 아니라 그 글의 갱신이 맞을 수 있다고 알린다.

### 3. 사용자에게 보이고 묻는다

표는 아래 칸으로 보인다. 스크립트가 찍은 표에서 '화제 번호' 칸은 빼도 된다(번호와 화제 번호의 짝은 세션이 기억한다).

| 칸 | 내용 |
|---|---|
| 번호 | 고를 때 쓰는 줄 번호 |
| 제목 | 판의 대표 제목 그대로 |
| 분야 | 판의 분야 |
| 며칠째 | 며칠째 이어지는지와 구역(새로 뜬 것, 이어지는 것) |
| 매체 | 매체 계열 수. 기준일이 아직 끝나지 않은 날이면 "오늘 N곳, 어제 M곳" |
| 민감 | 없음, 주의, 높음. 높음에는 '덱 제외'. 판에 민감 칸이 아직 없는 줄은 스크립트가 찍은 대로 '정리 전' |
| 한 줄 | 판에 한 줄 설명과 왜 지금인가가 있으면 그것, 없으면 상태 줄과 기사 수와 화제 점수 |
| 이미 | 2단계에서 찾은 것 |

표 아래에 붙이는 것: 기준 시각 한 줄(경고가 있었으면 그 문장), 검색에서만 보이는 낱말 줄, 버려서 접어 둔 줄 수.

물음은 한 번에, 아래 꼴로 한다.

> 만들 것의 번호와 버릴 것의 번호를 알려 주세요. 표에 없는 주제는 제목으로 주시면 됩니다.
> 예: "2, 5 만들기. 7 버리기. '가람역 환승 통로 폐쇄'도 만들기."
> 고르기만 하고 만들기는 나중에 하려면 "고르기만"이라고 덧붙여 주세요.

- 검색에서만 보이는 낱말을 고르면 그 낱말을 제목으로 직접 넣은 것으로 다룬다.
- 사용자가 다른 분야나 낱말로 다시 보자고 하면 1단계로 돌아간다. 다시 찍은 표는 번호가 달라진다. 고르기는 마지막에 보인 표의 번호로 받는다.
- 사용자가 아무것도 고르지 않으면 기록을 쓰지 않고 끝낸다.

### 4. 답을 기록한다

사용자가 준 번호를 표의 화제 번호(`t…`)로 옮겨 한 번에 적는다. 고른 순서를 지킨다.

```bash
.venv/bin/python .claude/skills/ozl/find/board_view.py note --pick t20990101-002 t20990101-003 --drop t20990101-007 --add "가람역 환승 통로 폐쇄"
```

- `--pick` 은 고른 것, `--drop` 은 버린 것, `--add` 는 직접 넣은 제목이다(`--add` 는 제목마다 한 번씩 준다). 셋 가운데 있는 것만 준다. 버리기만 해도 기록한다. 출력의 "고른 것 N건"은 고른 것과 직접 넣은 것을 합친 수다(둘 다 만들 건이다). 사용자에게는 고른 것, 직접 넣은 것, 버린 것을 따로 세어 알린다.
- 직접 넣을 제목은 기록하기 전에 `BV --match <제목의 핵심 낱말>` 로 판에 같은 사건의 줄이 있는지 본다. 같은 사건인 줄이 하나면 그 화제 번호를 `--pick` 에 넣고 그렇게 알린다. 없거나 확실하지 않으면 받은 제목 그대로 `--add` 한다.
- 기록은 `<자료 루트>/find/<타임코드>.json` 에 쓰이고, 출력에 기록 파일 경로, 고른 건마다의 key(`t…` 또는 `a…`)와 만들기 명령이 나온다. 이 key 와 경로를 만들기로 넘긴다.
- 버린 건은 사흘 동안 표에서 접힌다(`--all` 로 다시 본다). 운영 화면의 [버리기] 기록과는 따로다.
- "후보 판에 없는 화제 번호"로 거부되면 그 사이 판이 바뀐 것이다. 표를 다시 찍어 번호를 확인한다.
- 민감 높음인 건을 골랐으면 출력의 "민감 높음" 줄을 사용자에게 그대로 알린다: 덱은 만들지 않고, 글도 만들기의 0절(사람에 관한 의혹, 선거 판세, 사생활이 중심인 소재)에 걸리면 멈춘다.

### 5. 넘긴다

- 사용자가 "고르기만"이라고 했으면 기록 파일 경로와 고른 건 수를 알리고 끝낸다. 남은 건은 나중에 인자 없는 `/ozl make` 가 꺼낸다(최근 사흘의 기록에서 `대기` 인 줄. `BV picks` 로 본다).
- 그렇지 않으면 고른 순서대로 **한 건씩** `SKILL.md` 의 만들기(3절 1단계 「대상 정하기」의 둘째 길)로 간다. 대상은 화제 번호 또는 제목, 단서 파일은 방금 쓴 고르기 기록이다. 한 건이 끝나면(8단계) 상태와 남은 것을 알리고 다음 건으로 간다. 여러 건을 동시에 만들지 않는다.
- 사용자가 고른 것 가운데 일부만 지금 만들라고 했으면 그 건만 만든다. 나머지는 고르기 기록에 `대기` 로 남기고(나중에 인자 없는 `/ozl make` 가 꺼낸다) 그렇게 알린다. 만들기 8단계의 "다음 건으로 간다"보다 사용자의 말이 앞선다.
- 만들기 중에 멈춘 건이 있어도(사건을 확인하지 못함, 다루지 않는 소재) 까닭을 알리고 다음 건으로 간다.

## 돌려줄 것

기준 시각, 보인 줄 수, 고른 건과 버린 건과 직접 넣은 건의 수, 고르기 기록 파일 경로, 그리고 만들기로 넘어갔으면 건마다 이슈 번호와 상태('게시 대기' 또는 '검토 대기')와 남은 것. 승인은 사용자가 운영 화면 `/approve` 에서 한다.
