# /syuka ad — 광고와 협업 회차 (본 세션용)

광고주나 협업 기관이 소재나 자료를 건넨 회차(유료 광고, 협찬, 공공기관 협업)에서 일반 회차(`/syuka deck`)에 더하는 일이다. 일반 회차의 규칙은 그대로이고 여기에는 더하는 것만 적는다. 절차의 정본은 비공개 문서 `private/decks/규칙/광고_협업_절차_20261115_025107.md`(비공개 사본이 있는 기기에서만 읽힌다)이고, 코드가 보는 것은 `agent/deck.md` 의 「광고·협업 회차」에 있다. 절차 문서는 광고 칸 검사가 들어오기 전에 쓴 것이다. 절차 문서와 이 지시서가 어긋나면(사양의 광고 칸의 꼴, 민감 '주의' 카드를 만들 수 있는가, 점검 기록을 두는 자리) 이 지시서와 `agent/deck.md` 와 코드를 따른다.

자리표시: `PY` 는 `.venv/bin/python`(저장소에서 부른다). `<기록 폴더>` 는 `private/desk/builds/<card_id>/ad/` 다(완성 절차의 진행 기록과 같은 카드 폴더 아래. 비공개).

|---|---|---|

| 광고 구간의 위치와 길이 | 본편의 어느 단계 뒤에 몇 장인지. 길이는 장수로 받는다(검사가 장수를 센다). 광고주가 초나 분으로 바랐으면 그 값을 표시 계획에 적고, 장마다의 초는 사양을 쓸 때 정한다. 회차 전체가 광고면 그렇게 | 사용자에게 묻는다(길이는 사람이 정한다) |
| 표시 문구 | "유료 광고 포함", "협찬 포함" 같은 한글 문구. 사용자가 정한 것을 쓴다. 광고주가 다른 문구를 바랐으면 대조표에 광고주의 요청으로 적고 따르지 않은 까닭을 단다 | 종류에 맞는 문구를 제안하고 사용자가 정한다 |

사람이 정하는 것은 셋이다: 회차를 맡을지, 광고 구간의 길이, 공개. 공개는 사용자가 그렇게 말했을 때만 한다. 회차를 맡을지는 민감 점검(2단계)을 마친 뒤, 표시 계획을 쓰기 전에 대조표와 민감 점검의 독립 점검(2-1)까지 하고 대조표의 판정별 줄 수, 민감 점검의 결과, 독립 점검에서 갈린 줄을 보이고 묻는다(규제 산업은 2단계의 문서를 읽기 전에 먼저 묻는다). 사용자가 부르면서 이미 맡는다고 했으면 다시 묻지 않지만, 독립 점검은 그대로 한다(대조표의 판정이 사양에 들어가기 때문이다).

## 내는 것

- `<기록 폴더>` 에 셋: 광고주 자료 대조표(`대조표_<타임코드>.md`), 민감 점검 기록(`민감_점검_<타임코드>.md`), 광고 표시 계획(`표시_계획_<타임코드>.md`). 작업 기록이라 PDF 쌍을 만들지 않는다(사용자가 문서로 달라고 하면 그때 만든다). 이 셋은 완성 절차의 진행 기록(`PY -m ozl.render progress`)에 단계가 없다. `--mark` 를 부르지 않고, 사양 단계를 표시할 때 메모(`--note`)에 기록 폴더의 경로를 적는다(사양 단계를 이미 표시한 뒤에 기록 셋이 생겼으면 광고 칸을 넣은 다음 판의 사양을 표시할 때 적는다).
- 광고 칸이 든 사양. 덱 산출 폴더(pptx, PDF, 쪽 그림, 러닝시트, 링크 목록, 그림 검수 대장)는 완성 절차(`skills/ozl/SKILL.md` 의 5절)가 만든다.

## 하지 않는 것

- 광고주 자료만으로 수치를 쓰지 않는다. 광고주가 준 수치, 표, 그림, 문구는 그 자체로는 근거가 아니다.
- 광고주가 가공한 표를 원문 대신 쓰지 않는다. 광고주가 고른 비교 기준을 그대로 받지 않는다.
- 금융 상품, 건강 주장, 규제 산업, 공공기관 협업 갈래는 그 갈래의 법령과 심의 규정(1차 문서)을 읽기 전에 사양과 덱으로 넘어가지 않는다.
- 광고주 제공 자료를 외부 모델에 보내는 길은 「긴 자료 맡기기」(읽기와 1차 정리) 하나뿐이다. 검토 목적으로 외부로 나가는 것은 완성 절차의 검토 묶음과 아래 2-1 의 점검 묶음(공개 1차 자료와 대조표의 요약만 담은 것)뿐이다. 대조표의 판정(원문으로 받침, 광고주 제공으로만 소개, 쓰지 않음)과 민감 점검의 초안은 본 세션이 쓰고, 그 판정을 외부 모델이 대신 정하게 하지 않는다.
- 전사 문장과 슬라이드 문구를 기록과 사양에 옮기지 않는다(일반 회차와 같다). 광고주 자료의 문장도 대조표에 길게 옮기지 않고 자기 말로 줄여 적는다.
- 표시 문구를 영문 약어만으로 쓰지 않는다.
- 광고주에게 덱을 보내거나 공개하지 않는다. 사용자에게 원문 대조를 요청하지 않는다.

## 순서

사양을 쓰기 전에 하는 것이 순서다. 사양을 이미 쓴 뒤에 불렸으면 기록 셋을 만들고, 다음 판의 사양에 광고 칸과 광고 구간의 장을 넣는다(고친 판은 완성 절차의 검사와 검토를 처음부터 다시 받는다).

### 1. 광고주 자료 대조표

자료 폴더의 문서를 읽고, 덱에 쓰일 수 있는 주장을 한 줄씩 뽑아 아래 칸으로 적는다. 자료가 한 파일 6만 자 이상이거나 합계 10만 자 이상이면 직접 Read 하지 않고 `python3 ~/.claude/scripts/offload.py run --task extract --caller ozl:syuka-ad --prompt-file <기록 폴더>/offload_p.txt --in <자료…> --out <기록 폴더>/offload_claims.json --expect json` 으로 주장, 수치, 자료의 자리(파일 이름과 쪽이나 항목)를 뽑게 하고 결과 파일만 읽는다(`SKILL.md` 의 「긴 자료 맡기기」). 대조표에 올릴 수치는 결과가 가리킨 자리를 자료에서 `grep` 으로 열어 표기를 확인한다. 짧은 자료는 종전대로 직접 읽는다. 뽑은 주장을 원문(T1, T2)으로 받치는 일과 판정은 이 세션이 한다.

| 칸 | 내용 |
|---|---|
| 번호 | 대조표 안의 줄 번호 |
| 광고주 자료의 주장 | 자기 말로 줄여 적는다. 수치는 자료의 표기 그대로 |
| 자료의 자리 | 파일 이름과 쪽이나 항목 |
| 수치가 있는가 | 있음, 없음 |
| 찾은 원문 | T1, T2 문서의 기관, 주소, 원문의 자리. 찾지 못했으면 "찾지 못함"과 찾아본 곳 |
| 기록 번호 | 원문으로 받친 주장의 검증 기록(`<card_id>-cN`) |
| 판정 | 원문으로 받침 / 광고주 제공으로만 소개 / 쓰지 않음 |
| 까닭 | 판정의 까닭 한 줄 |

- **원문으로 받침**: 공시, 정부 통계, 기관 보도자료, 논문 같은 T1, T2 원문에서 같은 주장을 다시 찾았다. 일반 회차와 같이 검증 기록으로 만들고(`deck/01_card.md` 의 1단계, 완성 절차의 원문 사본과 재대조) 덱에서는 그 기록을 인용한다. 광고주 자료가 원문 출처를 알려 주면 그 원문을 직접 받아 대조한다.
- **광고주 제공으로만 소개**: 원문으로 받치지 못했지만 소개가 필요한 주장이다. 수치 없이 "광고주 제공 자료에 따르면"으로 주체를 밝혀서만 쓰고, 자료 이름을 사양의 광고 칸 `materials` 에 올린다(링크 목록에 「광고주 제공 자료」 절로 따로 나온다). 자료 이름은 보낸 곳, 무엇, 받은 날이 드러나게 적는다(지어낸 예: "두레페달 홍보팀 제공 자료(2099-01-02 받음)").
- **쓰지 않음**: 원문이 없는 수치, 경쟁사를 깎아내리는 비교, 원문 없는 "최고, 최초, 유일", 수익이나 효과를 보장하는 말. 경쟁사나 다른 상품과 견주는 수치는 양쪽 다 같은 기준의 원문이 있을 때만 받침으로 올린다.
- 웹을 여는 규칙은 `deck/01_card.md` 의 1단계와 같다(`robots.txt` 먼저, 같은 사이트 2초 간격, 막히면 멈춤).

### 2. 민감 점검

카드의 민감 표시(`sensitivity`)는 일반 회차 그대로 둔다. 광고와 협업 회차는 아래 네 갈래를 따로 본다.

| 갈래 | 따로 보는 것 | 1차 문서 |
|---|---|---|
| 정부와 공공기관 협업 | 정책 홍보와 사실 전달을 가른다. 정치색이 뚜렷한 정책은 맡지 않는다. 민간 광고주가 공공기관과의 제휴나 협약을 주장만 하는 것은 이 갈래가 아니다(그 주장은 대조표에서 그 기관 쪽 원문으로 받치지 못하면 쓰지 않는다. 받쳐서 쓰게 되면 이 갈래를 다시 본다) | 아직 읽지 않았다 |
| 금융 상품(예금, 투자, 보험, 대출) | 수익률과 금리의 표현, 위험 고지, 광고 심의 요건 | 아직 읽지 않았다 |
| 건강 주장(식품, 건강기능식품, 의료) | 효능의 표현, 심의 요건 | 아직 읽지 않았다 |
| 규제 산업(주류, 담배, 도박성 서비스 등) | 맡을지부터 사람이 정한다 | 아직 읽지 않았다 |

- "아직 읽지 않았다"는 그 갈래의 법령과 심의 규정을 절차 문서를 쓸 때 열어 읽지 않았다는 뜻이다(2026-11-15 기준).
- 이 회차가 네 갈래 가운데 하나에 해당하면 그 갈래의 1차 문서(법령, 고시, 심의 규정의 본문)를 먼저 읽는다. 읽은 문서의 이름, 주소, 읽은 날, 읽은 범위를 기록에 적는다. 읽지 못했으면 대조표와 이 기록까지만 만들고 멈춘 뒤, 무엇을 읽지 못했는지 사용자에게 알린다.
- 규제 산업은 문서를 읽기 전에 맡을지를 사용자에게 먼저 묻는다.
- 기록의 칸: 갈래, 해당하는가, 따로 본 것, 읽은 1차 문서, 결과(진행 / 멈춤 / 사람이 정함). 어느 갈래에도 해당하지 않으면 그렇게 한 줄로 적는다.

### 2-1. 대조표와 민감 점검의 독립 점검 (2026-11-21)

회차를 맡을지 묻기 전에, 본 세션이 쓴 대조표와 민감 점검을 쓴 쪽이 아닌 눈으로 한 번 더 본다. 쓴 세션이 스스로 채점하지 않는다.

- **다른 에이전트(읽기 전용)**: 대조표, 민감 점검 기록, 대조표가 인용한 원문 사본(T1, T2)의 경로, 광고주 자료 폴더의 경로를 준다. 줄마다 판정(원문으로 받침, 광고주 제공으로만 소개, 쓰지 않음)이 원문과 맞는지, 민감 갈래를 빠뜨리지 않았는지를 보고 "맞음, 고칠 것, 판정 못 함"과 까닭 한 줄을 돌려받는다. 답은 `<기록 폴더>/독립점검_<타임코드>.md` 에 받은 그대로 둔다.
- **다른 계열(공개 근거로 가능한 줄만)**: 원문으로 받친 줄 가운데 수치나 비교가 든 줄과, 표시 문구가 그 회차의 이해관계를 바르게 적었는지는 다른 모델 계열이 반박 검토할 수 있다. 보내는 것은 공개 1차 자료의 주소와 해당 대목, 대조표의 그 줄 요약, 표시 문구와 구간 계획뿐이다. 광고주 자료 원문, 광고주와 주고받은 글, 일반인을 알아볼 수 있는 정보는 넣지 않는다.
- 갈린 줄은 더 보수적인 판정(쓰지 않음 → 광고주 제공으로만 소개 → 원문으로 받침 순)으로 고치거나 원문을 다시 읽어 정하고, 고친 까닭을 대조표의 까닭 칸에 적는다.
- 결과는 게이트 원장에 남긴다: `python3 ~/.claude/scripts/offload.py gate --record --target syuka-ad:<card_id> --author-family claude --checker-lane <레인> --checker-model <모델> --verdict PASS|REVISE`. 다른 계열 점검을 하지 못했으면(공개 근거로 확인할 줄이 없음, 한도, 응답 없음) `offload.py gate --skip --target syuka-ad:<card_id> --reason "<사유>"` 로 남기고, 사용자에게 보이는 표에 "다른 계열 점검 없음: <사유>"와 확인하지 못한 줄을 적는다.

### 3. 광고 표시 계획

표시의 바탕은 「추천ㆍ보증 등에 관한 표시ㆍ광고 심사지침」(공정거래위원회예규)이다. 그 지침에서 읽은 것과 읽지 못한 것은 절차 문서의 2절, 6절, 7절에 있다. 계획에는 아래를 적는다.

- 종류, 광고주 이름, 표시 문구. 문구는 한글이고 "광고"나 "협찬" 낱말이 들어 이해관계가 드러나야 한다. 그것을 부정하는 말("광고 없음", "협찬 아님")은 검사에서 걸린다.
- 구간: 본편의 어느 단계 뒤에 몇 장인지, 본편(광고 아닌 장)이 몇 장인지. 구간은 한 덩어리로 두고, 여는 장보다 앞에 두지 않으며, 광고 아닌 장수의 20% 를 넘기지 않는다(우리가 정한 값이다). 회차 전체가 광고면 그렇게 적는다.
- 구간의 첫 장과 끝 장: 화면 글에 표시 문구와 광고주 이름을 넣고, 말로 할 문장에도 표시 문구를 넣는다(생방송에서 자막이 늦을 때를 대비한다). 두 장의 글 초안을 적는다.
- 광고주가 준 그림이 없으면 광고 장은 글만 있는 장이 된다. 장수가 적은 덱에서는 그 한 장으로 글만 있는 장 비율 경고가 난다. 직접 그린 도형을 둘지 계획에 적는다.
- 구간 안의 장마다 오른쪽 위에 띠("표시 문구 · 광고주 이름")가 찍힌다. 띠는 빌드가 그린다. 글이 길어 한 줄에 들어가지 않으면 검사에서 걸리므로 띠에 찍힐 글을 계획에 적어 길이를 본다.
- 덱 밖에서 할 것: 영상 제목이나 방송 화면 자막의 표시는 덱의 일이 아니다. 계획에 "덱 밖에서 할 것"으로 적어 사용자에게 알린다.
- 확인하지 못한 것: 플랫폼의 유료 광고 표시 정책과 이 절차의 관계는 확인하지 못했다(절차 문서 7절). 계획에 그대로 적는다.

### 4. 사양의 광고 칸

`src/ozl/render/spec.py` 에 광고 칸 검사가 있다(2026-11-15 에 확인했다). 사양을 쓸 때 아래를 넣는다. 칸의 뜻과 실패 조건의 전부는 `agent/deck.md` 의 「광고·협업 회차」에 있고 여기에는 옮겨 적지 않았다.

- 사양 맨 위에 `sponsorship` 칸: `kind`(유료 광고, 협찬, 협업 가운데 하나), `sponsor`(광고주 이름), `label`(표시 문구), `whole`(회차 전체가 광고면 참), `materials`(광고주 제공 자료의 이름들. 대조표에서 "광고주 제공으로만 소개"로 판정한 것).
- 광고 구간의 장에 `stage: 광고`. 본편의 흐름(여는 장, 배경, 전개, 반전, 비교, 닫는 장) 안에 광고 내용을 섞지 않는다. 회차 전체가 광고면 `whole` 을 참으로 두고 장의 단계는 그대로 쓴다.
- 광고주가 준 그림은 그림 검수 대장에 `기업 뉴스룸` 종류(로고는 `로고`)로 올리고 사용 허락 기록을 남긴다. 허락이 문서로 없으면 쓰지 않는다.
- `PY -m ozl.render check <사양>` 이 표시 문구와 구간의 짜임을 본다. 실패가 0 이어야 한다. 출력의 "본편 N장"은 광고 장까지 센 수다. 20% 는 광고 아닌 장수로 센다.
- 코드가 보지 않는 것이 있다: 광고주 자료에만 있는 주장이 화면이나 말에 들어갔는가, 금지 문장(경쟁사 깎아내리기, 원문 없는 최상급, 효과 보장), 표시 문구가 이 회차의 이해관계를 바르게 적었는가. 완성 절차의 문장 대조 지시서에 이 셋을 대조 항목으로 더하고, 대조표의 경로를 함께 준다.
